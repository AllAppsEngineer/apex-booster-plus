3. Local Device Readings

The app performs the following local readings for informational purposes:

  • Available and total RAM: reads the device's memory to display the session snapshot. Never leaves the device.
  • Basic network latency (Apex Ping): the app sends a simple network request (HTTP HEAD) to a public Google connectivity-check endpoint (clients3.google.com/generate_204, with connectivitycheck.gstatic.com/generate_204 as a fallback) solely to measure response time. No personal data is sent in this request beyond standard system HTTP headers, and the result (a number in milliseconds) is used only for on-screen display — it does not represent or promise the actual ping of external game servers. No video, audio, screen capture, clip, preference, game library data, or user-entered content is sent in this request. As with any network connection, the IP address and standard connection metadata may be observed by the destination infrastructure; retention of that data by the third party (Google) is not controlled or confirmed by Apex Booster+.
  • Focus Mode / Do Not Disturb (DND) status: checked only when the user grants notification policy access permission. It is not enabled automatically.

These readings do not generate any personal data sent to a server — the app's only network communication is the latency check above.

4. Installed Apps

To allow the user to select games from their library of installed apps, Apex Booster+ may list launchable apps available on the device.

  • No unrestricted access: the app does not request permission for unrestricted access to the full system app list (no QUERY_ALL_PACKAGES).
  • No external transmission: the list of installed apps is never sent to servers.
  • User control: the user decides which apps to add to the library. The app does not perform automatic scans or export this data.

5. Apex Studio — Screen Capture, Video Clips and Gallery Media

Apex Studio is the app's social content creation feature. It offers three ways to obtain media, all explicitly triggered by the user:

5.1 Gallery import

The user can voluntarily select an existing image or video on the device through Android's native media picker (image_picker). The file is read only in memory, during the session, for preview and card composition — it is never sent to servers and is not saved in the app's preferences.

5.2 Screen capture and video clips (Apex Floating Button)

With the Apex Floating Button enabled (optional — see section 7), the user can capture a screenshot or record a short video clip (10 to 60 seconds) of their own gaming session. This feature uses Android's MediaProjection API, which requires explicit user confirmation on the operating system's own consent screen before any capture starts, and keeps a persistent notification while capture is active.

  • In-game internal audio (optional, video only): when available, the app may capture the audio played by the game/app itself during recording (AudioPlaybackCaptureConfiguration API, Android 10 or higher). This is not the device's microphone — no voice or ambient sound is captured. The RECORD_AUDIO permission is required by the Android API for this feature even though it is internal app audio, due to a platform quirk; the physical microphone is never read in this configuration.
  • When audio is unavailable: some games block internal audio capture by their own policy. In these cases, the video is saved normally without audio, and the app shows a notice guiding the user to record externally (with the device's own screen recorder) and import the video via the gallery (section 5.1), if they want a clip with audio.
  • Storage: captures and clips are saved in a folder specific to Apex Booster+ inside the app's own storage (not a shared public gallery), with a local index (index.json) used only to list files inside Apex Studio.
  • Transmission: none. No screenshot, clip, or audio is ever sent to servers under any circumstance.

6. Export and Sharing

Apex Studio lets the user compose a visual card (image or video with an Apex frame) from selected or captured media. All composition — including video export — happens locally on the device, with no server-side processing step.

  • Always manual sharing: publishing only happens when the user taps "Share" and chooses a destination in Android's native share sheet. Apex Booster+ never automatically posts or publishes to any social network.
  • Temporary, restricted access: the exported file is made available to the destination app chosen by the user through a FileProvider with temporary permission — no other app has access to it.

7. Apex Floating Button (SYSTEM_ALERT_WINDOW)

The Apex Floating Button is an optional visual shortcut shown over other apps during a gaming session, used exclusively to quickly open the screen/video capture described in section 5.

  • Explicit opt-in: off by default. Only requested when the user enables the feature in Settings, with an in-app explanation shown before the system's own permission screen opens.
  • Reversible at any time: the user can disable the button in Settings, which removes the on-screen shortcut immediately.
  • No data collection: the button does not read, log, or transmit anything by itself — it only opens the capture flow described above.

8. One-Time Unlock (Google Play Billing)

Apex Booster+ uses the free install + one-time unlock model (no subscription, no ads). The purchase is processed entirely by the official Google Play Billing library, which communicates directly with Google Play's servers — Apex Booster+ never sees or stores card numbers, bank details, or payment information.

  • What the app receives: only a confirmation from Google Play stating whether the purchase was completed or restored. This confirmation is used to unlock the full experience and is mirrored locally as a boolean value (purchased/not purchased) in the device's SharedPreferences.
  • No transaction history in the app: Apex Booster+ does not keep a record of amounts, billing dates, or payment method — that history lives exclusively in the user's Google Play account.

9. Data Not Collected

Apex Booster+ does not collect any of the following data:

  • Name, e-mail, or any personal identifier of the user.
  • Precise or approximate location.
  • Contacts, messages, calls, or communication data.
  • Physical microphone audio or conversations.
  • Card numbers, bank details, or payment information.
  • Biometric data or advertising identifiers.

Photos, videos, and in-game internal audio are only accessed when the user explicitly triggers gallery import or the capture described in section 5 — never automatically, and never sent outside the device.

10. Data Sharing with Third Parties

Apex Booster+ does not sell, rent, or share personal data with advertisers, partners, or third parties. There is no:

  • Advertising SDK.
  • Third-party analytics or attribution SDK.
  • Behavioral tracking for advertising purposes.
  • Cookies or tracking technologies.

The official Google Play Billing library (used only for the one-time unlock, section 8) includes, as part of its own internal operation, standard Google Play Services components for the library's own diagnostics. These components are not configured or used by Apex Booster+'s own code for any analytics, advertising, or user-tracking purpose.

12. Data Retention and Deletion

  • Library, history and preferences: "Clear history" in Settings removes saved sessions; uninstalling the app deletes all local SharedPreferences data.
  • Screenshots and video clips: can be deleted individually by the user inside Apex Studio; uninstalling the app removes the entire associated folder.
  • Media imported from the gallery: discarded from the app's memory as soon as the Studio screen is closed; the original file remains only where the user had already saved it (system gallery), outside Apex Booster+'s control.
  • Unlock status: removed when the app is uninstalled; can be restored at any time via the "Restore purchase" button, which queries Google Play again.

Since Apex Booster+ has no server of its own, there is no data retention outside the user's device.

13. Limitations and Important Notices

  • Apex Booster+ does not automatically modify third-party games.
  • The app does not promise actual improvement in FPS, GPU, resolution, ping, or performance of external games.
  • The displayed metrics (RAM, Apex latency) are local and informational — they do not represent automatic changes to the device or to the games.
  • Gamer Focus Mode enables Android's Do Not Disturb only when the user explicitly grants permission.
  • Screen capture, internal audio, and the floating button are gamer self-expression and personal organization features — not a competitive in-game advantage.

14. Data Security

Preferences and history data are protected by Android's app sandbox and the device's file system encryption. Screenshots and clips live in a folder specific to the app, not accessible to other apps without the user's explicit permission. The app's only two network communications — the latency test (section 3) and purchase processing via Google Play Billing (section 8) — use the operating system's standard encrypted connection (HTTPS/TLS).

15. Children

Apex Booster+ is not directed at children under 13 and does not knowingly collect data from minors.
